# Сетевая карта 
Она мост между 2 мирами
- Электричество, радиоволны, свет
- Биты

1. Фильтрует - принимает/отбрасывает Ethernet-кадры, а коммутатор решает, на какой порт физически отправить кадр
2. Чтобы процессор не тратил время на перекладывание каждого байта, сетевая карта через шину PCIe сама записывает принятые байты напрямую в оперативную память
3. Записав пакет в память, карта шлёт процессору аппаратный сигнал (IRQ): «Пакет в оперативной памяти, забирайте».

# Порт
Порт — 16-битное число, идентифицирующее конечную точку транспортного протокола (TCP/UDP). ОС использует порт вместе с IP-адресами и протоколом, чтобы определить соответствующий сокет.
- Есть **системные порты** (0 - 1023) для базовых протоколов
- Пользовательские (1024 – 49151)

Общепринятые стандарты для базовых протоколов: 80 (HTTP), 443 (HTTPS), 22 (SSH), 53 (DNS).

Listening socket принимает новые TCP-соединения. После установки соединения создаётся отдельный connection socket, через который идут байты конкретного клиента.

# Протокол
Протокол — это просто формализованный договор (спецификация) между разработчиками разных программ: как форматировать данные, как их расшифровывать и что делать в ответ.

У него есть **стандарты**:
1. Синтаксис (Формат сообщения)
2. Семантика (Смысл команд и данных)
3. Сценарий взаимодействия (Тайминги и очередность)

# Сокет
Сокет - это точка взаимодействия, которая выполняет роль посредника. Ну или реализация эндпоинта внутри операционной системы для работы с **сетью**(конкретно
в нашем случае)

Есть и не сетевые сокеты:
1. Локальные межпроцессные сокеты 
3. Сокеты виртуализации
3. Системные сокеты
4. Аппаратные сокеты для шин и контроллеров

Функции:
- Буферизует(сохраняет) данные (держит входящую/исходящую очередь).
    На всякий случай, если вдруг что
- Передаёт программе данные конкретного соединения. 
    отсекает любой посторонний трафик и пропускает в твою программу только байты, принадлежащие конкретному сеансу связи.
- Следит за состоянием разговора (State Machine)
    TCP хранит состояние соединения: устанавливается, работает, закрывается и т.д.
- Превращает сетевую магию в простые действия «читать/писать»
    Сокет переводит вызовы твоего языка программирования (recv, send) в низкоуровневые команды операционной системы, избавляя тебя от необходимости вручную нарезать пакеты и работать с железом.

Одновременно сокетов может быть очень много
У одного локального порта сервера может быть множество TCP connection sockets

Когда ты со своего ПК одновременно сидишь на YouTube, GitHub и Telegram:
    У твоего компьютера один IP-адрес.
    Браузер под каждый сайт создаёт отдельный сокет.
    Операционная система выдаёт каждому сокету случайный временный порт (Ephemeral Port).

Но если это сервер, на котором запущено какое либо приложение на определенном порту, то *у каждого TCP-соединения есть свой socket, но серверная сторона всех этих сокетов может иметь один и тот же локальный порт.*

listening(TCP) socket — отдельная сущность. Он постоянно ждет. «Есть новые подключения?»
